## 試験層と環境

- ホスト単体試験: PlatformIO Unity。HALと時刻を差し替え、パーサ、変換、設定検証、状態遷移を決定的に試験する。
- ビルド・静的確認: generic/EVTとISP派生環境、将来のRelease/Debug構成、リンクマップ、未使用機能と動的確保の確認。
- HIL: EVT、WCH-Link、PC/BIDS_Server、CANトランシーバとマスター、オシロスコープ/ロジックアナライザを使用する。
- 結合・故障注入: ESP32マスター供給後にLSS/PDO/EMCY等を確認する。マスターが未提供の試験は「未実施・依存待ち」と記録する。

重要ロジック（プロトコル解析、変換、設定検証、状態遷移）の分岐カバレッジ90%以上を目標とする。SDK/HAL/外部スタックへ同じ数値を一律に課さない。測定ツール、除外一覧、CIコマンドはO-17。低影響の文書変更にはファームウェア実機試験を要求しない。

## 境界・異常試験の補足

入力は正常値だけでなく、ゼロ長、最大長、最大長+1、途中切断、連結フレーム、不正数値、未知コマンドを試す。可変構造は4/5個、16/17フィールド、名前15/16文字、値256/257 byteを境界として扱う。受信バイト列の分割位置を変えても結果が変わらないことを確認する。

時間試験には仮想時計で閾値直前/一致/直後を確認する単体試験と、実機の観測を併用する。通信タイムアウト3秒の後にさらに出力保持3秒を加算する実装を見逃さない。故障復帰は通信回復だけで出力が不用意に再開しないかを確定した状態表に照らす。

32 bitシリアルの理論的衝突は大量の実機試験だけでは排除できない。CRC既知ベクトルと全UID公開を検証し、衝突を受容する試作判断と製品向け課題を記録する。

## コマンドと実施記録

2026-09-17のスキル環境整備で、既存点滅サンプルの4環境ビルドが成功した。Core版・サイズ・確認範囲は [tooling-environment.md](tooling-environment.md) に記録した。これは下記要求ベース試験の合格や実機検証ではない。日常のビルド・書き込み手順は [PlatformIOスキルの参照文書](../skills/ch32v203-platformio/references/build-upload.md) を参照する。

既存のビルド確認コマンドは次のとおり。ホストUnity環境やcoverage設定はまだ存在しないため、それらの実行可能なコマンドは実装時に追加する。

```powershell
pio run -e generic -e evt -e generic_isp -e evt_isp
```

この環境で`pio`がPATHにない場合は次を使用できる。ユーザー固有パスをプロジェクトの移植可能な設定へ固定しない。

```powershell
& "${env:USERPROFILE}\.platformio\penv\Scripts\platformio.exe" run -e generic -e evt -e generic_isp -e evt_isp
```

将来の結果には試験ID、コミット、ビルド設定、ボード、配線、マスター/BIDS版、測定器、手順、期待値、実測値、合否、ログ保存先を記録する。HIL未実施をホスト試験で代替合格としない。仕様初版の文書化ではリンク・要求ID・未決参照・差分のみを確認した。その後のツール環境確認は上記の別記録で管理する。
