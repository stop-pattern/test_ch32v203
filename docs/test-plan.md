# 試験計画

記録日: 2026-09-17。状態: ファームウェアの要求ベース試験は未実施。開発手順の文書レビューとファームウェアのビルド・実機試験は別々に記録し、一方を他方の合格根拠にしない。

要求は [requirements.md](requirements.md)、数値・外部契約は [interface-spec.md](interface-spec.md) を参照する。未決IDは [decisions.md](decisions.md#未決事項台帳) に対応する。仕様未確定の試験を推定期待値で合格にしない。

## 試験層と環境

- ホスト単体試験: PlatformIO Unity。HALと時刻を差し替え、パーサ、変換、設定検証、状態遷移を決定的に試験する。
- ビルド・静的確認: generic/EVTとISP派生環境、将来のRelease/Debug構成、リンクマップ、未使用機能と動的確保の確認。
- HIL: EVT、WCH-Link、PC/BIDS_Server、CANトランシーバとマスター、オシロスコープ/ロジックアナライザを使用する。
- 結合・故障注入: ESP32マスター供給後にLSS/PDO/EMCY等を確認する。マスターが未提供の試験は「未実施・依存待ち」と記録する。
- 開発手順の検証: [development-workflow.md](development-workflow.md) に従う記録、再開、修正・再検証、並列作業の管理をレビューする。実機不要の確認と、実装・書込みの許可後に行う実証を区別する。

重要ロジック（プロトコル解析、変換、設定検証、状態遷移）の分岐カバレッジ90%以上を目標とする。SDK/HAL/外部スタックへ同じ数値を一律に課さない。測定ツール、除外一覧、CIコマンドはO-17。低影響の文書変更にはファームウェア実機試験を要求しない。

## 境界・異常試験の補足

T-20ではビルドログの実際のC++言語指定とコンパイラの言語版マクロを確認し、C++20設定の宣言だけで対応済みとしない。採用する標準ライブラリ機能を対象ツールチェーンで検証し、SDK/スタックがCとしてビルドされること、C++境界でのリンケージ、割込みエントリとWCH属性を確認する。対象実機でのISR動作は、実装と実機操作が許可された後に測定する。既存Cサンプルのビルド成功はC++20対応の検証を代替しない。

T-24の対象・命名・整形・コメントの判定はcoding-styleを正本とする。SDKやCANopenNodeの上流ソースは規約適用のために変更せず、必要なABI名・ISR名・レジスタ名の例外を確認する。既存コードの一括整形や命名修正は今回行わない。formatter/linterは未設定であり、導入前はレビューで確認し、導入時に固定版と検査コマンドを記録する。

入力は正常値だけでなく、ゼロ長、最大長、最大長+1、途中切断、連結フレーム、不正数値、未知コマンドを試す。可変構造は4/5個、16/17フィールド、名前15/16文字、値256/257 byteを境界として扱う。受信バイト列の分割位置を変えても結果が変わらないことを確認する。

時間試験には仮想時計で閾値直前/一致/直後を確認する単体試験と、実機の観測を併用する。通信タイムアウト3秒の後にさらに出力保持3秒を加算する実装を見逃さない。故障復帰は通信回復だけで出力が不用意に再開しないかを確定した状態表に照らす。

32 bitシリアルの理論的衝突は大量の実機試験だけでは排除できない。CRC既知ベクトルと全UID公開を検証し、衝突を受容する試作判断と製品向け課題を記録する。

## コマンドと実施記録

2026-09-17のスキル環境整備で、既存点滅サンプルの4環境ビルドが成功した。Core版・サイズ・確認範囲は [tooling-environment.md](tooling-environment.md) に記録した。これは本書の要求ベース試験の合格や実機検証ではない。日常のビルド・書き込み手順は [PlatformIOスキルの参照文書](../skills/ch32v203-platformio/references/build-upload.md)、反復作業・証拠保存・資源管理は [development-workflow.md](development-workflow.md) を参照する。

既存のビルド確認コマンドは次のとおり。ホストUnity環境やcoverage設定はまだ存在しないため、それらの実行可能なコマンドは実装時に追加する。

```powershell
pio run -e generic -e evt -e generic_isp -e evt_isp
```

この環境で`pio`がPATHにない場合は次を使用できる。ユーザー固有パスをプロジェクトの移植可能な設定へ固定しない。

```powershell
& "${env:USERPROFILE}\.platformio\penv\Scripts\platformio.exe" run -e generic -e evt -e generic_isp -e evt_isp
```

結果には試験ID、コミットと未コミット差分、ビルド設定、生成物の識別情報、ボード、配線、マスター/BIDS版、測定器、手順、期待値、実測値、合否、ログ保存先を記録する。反復ごとの結果は [work-log.md](work-log.md) へ、現在の到達点と次の検証は [progress.md](progress.md) へ反映する。詳細ログの保存と保持は開発手順に従う。HIL未実施をホスト試験で代替合格としない。仕様初版の文書化ではリンク・要求ID・未決参照・差分のみを確認した。その後のツール環境確認は上記の別記録で管理する。
