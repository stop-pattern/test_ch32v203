# インターフェース仕様

記録日: 2026-09-17。状態: 合意済み契約と未決項目のスナップショット／未実装。

要求IDは [requirements.md](requirements.md)、未決IDは [decisions.md](decisions.md#未決事項台帳) を参照する。下記の既定値は今回の試作向けである。未決のワイヤ形式・レジスタ方式・エラー番号を実装時に推測してはならない。

## 1. ボード・GPIO

対象はCH32V203C8T6系のgeneric/EVTプロファイル。Flash 64 KB、RAM 20 KBを前提とする。EVTの実配線、各クロック、LEDジャンパーは確認待ち（O-01/02）。カスタム基板の割当ては未決（O-03）。

| 信号 | 試作ピン案 | 方向・既定 | 備考 |
|---|---|---|---|
| USB D-/D+ | PA11/PA12 | USB Device CDC | Hostにはしない |
| CAN RX/TX | PB8/PB9 | CANリマップ | 外付けトランシーバを使用 |
| PWM | PA0 / TIM2_CH1 | 出力、安全値0 | 16 bit論理値 |
| ADC | PA1 | アナログ入力、可変抵抗の位置入力を想定 | 12 bit、電圧・実配線・校正/診断上下限はO-03/09 |
| DI | PA2 | 入力、内部pull-up、active-low | 1 msサンプリング |
| DO | PA3 | push-pull、active-high、安全値Low | 論理0で安全 |
| RUN LED | PC0 | 出力、緑 | LED回路・極性はO-01 |
| ERROR LED | PC1 | 出力、赤 | 現在のサンプルもPC1を使用 |
| モード選択 | PC2 | 入力、pull-up、High=USB、Low=CAN | 未接続時USB。20 ms連続安定で切替確定、実配線はO-01 |
| デバッグUART | PA9/PA10 | ビルド時選択 | 通信条件はO-14 |
| WCH-Link | PA13/PA14 | SDI | デバッグ・書込み用 |

電気的保証は3.3 V MCU論理信号までとし、直接の計器・電力負荷駆動を保証しない。入力許容電圧、外部プル、リセット中の信号状態は使用MCUと基板仕様に従う。PB2は起動設定との競合を避け、代替ピンとして安易に使用しない。ピン表は実機検証が済むまで暫定とする。

## 2. 操作経路と設定反映

| ビルド方針 | GPIO=USB | GPIO=CAN | 状態 |
|---|---|---|---|
| GPIO厳密選択 | USBのみ | CANのみ | 既定 |
| GPIO＋USB優先 | USBを優先し、使用不可時はCAN | CANのみ | 選択可能 |
| 接続USB優先 | USB使用可能ならUSB、それ以外CAN | 左記と同じ | 選択可能、GPIOに依存しない |

「USB使用可能」はBIDS正常通信とDO/PWMに必要な出力値の取得が揃うこととする。列挙・DTR等の下位条件との対応はO-06/15。出力指令とDI/ADC由来の操作は選択経路に限定する。状態・診断は両接続経路から参照可能だが、BIDSが定義しない独自通知は追加しない。

経路切替は新経路のDO/PWM指令が両方揃ってから一括で行う。最大3秒で揃わなければ両出力を安全値にする。押下中のDI/Hornは旧経路へ可能な範囲で解放を通知し、新経路では解放・再押下まで押下通知を抑止する。断線した旧経路への解放到達は保証しない。切替と故障の同時発生、故障中のイベント処理はO-06。

USB/BIDSとMCU共通処理が正常なら、非選択CANのbus-off、NMT停止、マスター通信断でDO/PWMを停止しない。NMTの管理状態を必ず故障と見なすものではない。選択経路の通信故障からは、必要な運転条件（CANはOperational等）と新しい有効指令が揃ってから自動再開し、DO/PWMとも通信断前の指令を再利用しない。片側だけ新着した際の再開単位はO-06で確定する。

論理設定は揮発であり、再起動時はビルド既定値へ戻る。物理ピン、GPIO/PWM/ADCの種別、周辺機能割当てはビルド固定とする。

既定はPre-operationalでshadow設定を書き、明示的な反映要求に対する全体検証成功後に一括反映する。Operational遷移だけでは未反映設定を採用しない。不正値は有効設定を保持しSDO Abortを返す。EMCY併用条件と具体的コードはO-14。一括方式を無効化するビルドでは独立値だけ即時反映可能とする。複数項目のマッピングは常に整合した単位で反映する。applyオブジェクト、反映境界、独立値の一覧はO-04。

## 3. 論理データ型・変換

以下の型は論理契約であり、ODの型やワイヤ上のバイト配置まで確定するものではない。

| 項目 | 合意済み範囲・尺度 | 未決部分 |
|---|---|---|
| DI/DO | 論理0/1、極性は設定で変換 | PDO内のビット位置・OD型（O-07） |
| PWM指令・出力上限 | `uint16_t`、0～65535、USB/CAN共通の比例調整 | 丸め、100%端点、設定API・反映境界（O-02/04/11） |
| ADC生値 | 12 bit、0～4095 | OD上の容器型、平均値の丸め（O-07/11） |
| デバウンス時間 | 0～100 ms、既定5 ms | OD型（O-07） |
| 速度 | km/h、既定上限120 km/h、負速度は絶対値で換算 | 内部表現・演算精度（O-11/18） |
| ブレーキ | 解放0、常用1～B、非常B+1を想定し、ADC診断異常時は非常段を指令 | BIDS版差・非常段未取得時（O-08/09）。段数未取得時は指令を送らない |
| Node識別 | MCU UID 96 bit、LSS用シリアル32 bit | CRC方式・バイト順、他のIdentity値（O-20） |

変換機能は線形スケール、オフセット、論理/符号反転、min/maxクランプ、デジタル閾値、ヒステリシスとする。任意式・スクリプトは提供しない。適用順序、演算精度、オーバーフロー、ヒステリシス境界はO-11/18で決める。

### PWMと速度

速度上限`Vmax`はビルド時設定、初期値120 km/h。出力上限`Pmax`は通常設定とは独立した運転調整用の揮発値、初期値65535。選択経路からのみ変更可能で、正常出力中は現在の有効入力を用いて次の出力更新で再計算する。新たな速度/指令の受信を待たないが、安全状態や指令失効を解除しない。USB側の変更手段とCAN側のOD/APIはO-04/07/08で確定し、独自BIDSコマンドを仮定しない。USBは速度の絶対値、CANは0～65535の指令をPmaxへ比例変換する。整数化・丸めはO-11/18。

```text
USB: PWM論理値 = clamp(abs(速度) / Vmax, 0, 1) × Pmax
CAN: PWM論理値 = (PWM指令 / 65535) × Pmax
```

16 bit分解能を優先し、ARR=65535を使用する。アップカウント時の基本関係は次のとおり。

```text
PWM周波数 = タイマ入力クロック / ((PSC + 1) × (ARR + 1))
カウント数 = ARR + 1
```

| タイマ入力を144 MHzと仮定した例 | PSC | ARR | 周波数 | カウント数 |
|---|---:|---:|---:|---:|
| 約1.099 kHzの既定案 | 1 | 65535 | 1098.6328125 Hz | 65536 |
| 同じARRで分周なし | 0 | 65535 | 2197.265625 Hz | 65536 |
| 正確な1 kHzを優先する代替案 | 2 | 47999 | 1000 Hz | 48000 |

これは計算例であり、実クロックの検証結果ではない。概算周波数を許容する合意はあるが、実プロファイルのPSC/周波数はO-02で確認する。高周波化すると利用可能なカウント数が減る場合がある。論理最大値65535を単純にCCRへ書くだけでは厳密な100%にならない方式もあるため、端点の実現を別途規定する。

### DI・ADC・ブレーキ

- DIは1 ms周期で取得し、既定5 msの連続安定後に状態を変更する。デバウンス値はSDOで0～100 ms、揮発変更可能。範囲外は拒否する。
- ADCは1 kS/s、8標本移動平均を基準とする。標本周期の変更は処理時間の評価後に明示設定する方針とし、自動調整しない。
- ADCのCAN通知は既定4 LSB変化または最大100 ms。変化量と最大通知間隔はSDOで揮発変更可能とする。比較元、平均の丸め、設定範囲と時刻起点はO-19。
- ブレーキ段数を`TRIC0`で取得し、校正min/max、方向、ヒステリシスで段へ量子化する。起動・再接続時に段数を取得できるまではADC由来のブレーキ指令を送らず、取得を再試行して未準備状態を診断する。その間は非常ブレーキも確実には指令できない。非常段情報の欠落・版差の扱いはO-08/09、未準備診断の表示・公開方法はO-09/14。
- 診断上下限は校正値と別に設定し、初期値は診断無効。8標本平均値が診断窓外に100 ms連続したら異常とし、段数が取得済みなら非常ブレーキ指令と診断を行う。正常範囲が100 ms連続したら自動復帰し、現在の操作位置の指令へ戻す。通信不通時や非常段を取得できない場合の詳細はO-09。
- ADCは入力異常でも0～4095へ飽和し得る。範囲内の値だけから断線を保証して検出できるとはしない。実配線と診断窓の確認を有効化条件とする。

## 4. USB CDC・BIDS

| 項目 | 合意済み内容 |
|---|---|
| 役割 | USB Device、BIDSクライアント |
| 対応版 | v100/v202を識別し対応機能を扱う。具体的互換表はO-08 |
| テキスト | ASCII、`TR...`要求、応答・`TRE1`～`TRE8`等の解析 |
| バイナリ搬送 | `B64E`＋Base64＋改行。生バイナリの直接混在ではない |
| 行末 | LF/CRLF/CRを受信、LFで送信 |
| ラインコーディング | BIDS側既定19200・8N1を基準。USB物理転送速度とは分離 |
| 制御線 | BIDS側のRTS/DTR使用を考慮。CDCでの解釈はO-15 |
| 生存確認 | 既定1秒周期、通信タイムアウト既定3秒、設定候補範囲1～10秒 |
| データ取得 | B64E自動送信優先、代替ポーリングは必要な各データ20 Hzを目標 |
| デバッグログ | BIDS CDCには出力しない |

クライアントとしてTR要求・制御の全系列を生成し応答を解析する方針とするが、全コマンドの型・版差・照合規則・エコーの扱いはO-08で表にする。パーサが未知・不正・過大入力を安全に拒否することは確定している。再同期、エラー返信の可否、破棄単位は未決である。

バイナリ対象はSpec/State/Handle/Panel/Sound、可変構造登録・値。可変構造は4個まで、各16フィールド、名前15 ASCII文字、値ペイロード256 byteまで。Panel/Soundのペイロード用に512 byte共有領域を使う。これはヘッダを含む最大受信長とは異なる。参照実装の内部データ形式、最大長、名前の終端分の確保はO-08/11。

速度→PWM、ドア閉→DO、DI→Horn押下/解放、ADC→ブレーキをデモ既定とする。Hornのキー識別、ドア値の表現、ブレーキ非常段等はプロトコル表で固定する。任意の未定義通知を既存BIDSへ追加しない。

代替ポーリングは必要な各データを20 Hz（50 ms周期）で取得する目標とし、合計要求数の上限20回/秒という意味ではない。応答形式やまとめ取得による要求数と実現性はO-05/08/11で確認し、未達を自動的に適合扱いせず、実現困難なら要求の再判断を求める。自動送信中は生存確認が正常なら最後の速度・ドア値を保持し、確認用の定期読み直しは追加しない。通知だけが停止して生存応答が続く故障は検出できない可能性がある。push対応の判定、移行・復帰、応答照合、再試行はO-05に残す。無更新だけで断線やpoll移行と判定しない。

## 5. CAN・CANopen

物理CANはClassical CAN、既定500 kbit/s、ビルド時変更可能。試作条件は最大16ノード・40 m。トランシーバ、ESD保護、短いスタブ、切替終端は基板・配線側の要求で、ファームウェアだけで保証しない。コネクタの挿抜は全機器電源OFFとし、稼働バスへノードが遅れて起動するケースをソフトウェアで扱う。

| 項目 | 契約 |
|---|---|
| スタック | CANopenNode v4の固定版（具体的版はO-17）、slave専用 |
| 必須機能 | NMT slave、Heartbeat producer/consumer、SDO server、PDO、EMCY、LSS slave/Fastscan、CiA 303-3、必要なCiA 401 |
| 不使用機能 | SDO client、LSS master、不要なtrace/safety等 |
| 起動ID | 毎起動未設定、LSSで揮発割当て。割当て・活性化後のBoot-up/NMT手順はOD/状態表で固定 |
| ビットレート | 起動時既知の500 kbit/sを既定とする |
| Identity | 1018:04はCRC32(96 bit UID)、全UIDをメーカー固有ODに公開 |
| マスター監視 | 既定で有効、ビルド時無効化も選択可能。Node-ID 1、送信想定1秒、受信監視3秒 |
| 監視設定 | 監視対象IDと時間はSDOで揮発変更可能。OD/通信契約の具体値はO-07 |
| RPDO初期方針 | DO/PWMを入力する |
| TPDO初期方針 | DI/ADCと状態を出力する |
| PDO再設定 | 標準手順、Pre-operationalでのみ再マッピング |

ODはCiA 301/401の該当標準オブジェクトとメーカー固有設定・診断・UIDから構成し、EDSを提供する。CANopenへ公開するBIDS値は今回の制御・設定に使用する値と状態・診断に限定し、未使用BIDS値を網羅的に公開する機能は対象外とする。これは受信するバイナリ型の対応範囲を削除するものではない。インデックス、sub-index、型、単位、アクセス権、PDOマッピング可否、COB-ID、送信種別・周期はO-07で確定する。公開項目の具体一覧はO-18。

CRC32には衝突可能性があり試作では受容するが、アルゴリズムとバイト順はO-20。製品の重複防止方式は別途検討する。

## 7. 起動・終了・エラー

起動直後の可能な限り早いGPIO初期化でERRORを点灯し、DO/PWMは安全値にする。ローカル初期化成功後は通信状態に応じた通常表示へ移る。通信と最初の有効指令が揃うまで指令出力を開始しない。USB未接続、マスター不在は致命エラーではない。

明示的な終了コマンド、停電保存、PVD終了処理は設けない。電源OFF・リセット中の信号は外部プル等も含めた基板契約で扱う。

| エラー・事象 | 合意済み処理 | 未決 |
|---|---|---|
| 不正/範囲外SDO設定 | 拒否、有効設定を保持 | Abort/EMCY対応表O-14 |
| 不正/過大BIDS入力 | 出力へ適用せず安全に拒否・診断 | コード、再同期、応答O-08 |
| 通信断 | 規定監視後に安全値。復旧後は運転条件と新しい有効指令が揃えば自動再開 | 複合状態・事象別の細部O-06 |
| CAN bus-off | 選択CANでは安全値、自動復旧を継続。必要な運転条件と新しい有効指令で自動再開 | 再試行間隔・診断解除O-10。正常USB操作は停止しない |
| ADC診断異常 | 8標本平均の100 ms連続逸脱で非常ブレーキ、100 ms正常で自動復帰 | 段数未取得時は指令を送らない。閾値/非常段情報欠落等O-09 |
| 致命的初期化/内部整合異常 | 安全値、RUN消灯、ERRORコード点滅、ループ維持・WDT給餌 | コード一覧と致命分類O-14 |
| 通常ループ停止 | WDTリセット | 給餌条件と起動後原因表示O-14 |
| キュー飽和 | 連続値は最新値へ集約し、押下/解放イベントの順序保持を優先。保持不能は明示的異常として扱う | キュー長・飽和時の具体的安全処理O-11 |

CAN側はOD/EMCY、BIDS側は既存プロトコルで許された応答、LEDと専用ログで診断を提供する。正常USB操作中でも非選択CANの実際の通信故障をERROR LEDへ表示し、診断・ログに残す。意図的なNMT停止を必ず通信故障と扱うものではない。CiA 303-3をLED表示の基本にし、起動・致命コードを拡張する。全パターン、周期、複合異常の優先順位はO-14で表にし、未決の数値コードは割り当てない。

WCH-Link/SDIをログの既定バックエンド、UARTをビルド時選択とする。Releaseは起動・状態変化・異常を中心とし、通常の毎サンプル/毎フレーム出力は行わない。詳細通信追跡はDebugで有効化する。同じ論理ログを固定長・非ブロッキング・ヒープなしで扱い、項目・容量・上限はO-14。現在のPlatformIO monitor設定115200はBIDSの19200とは別で、将来UARTログ条件の決定を意味しない。

## 8. セキュリティと更新

USB/CANの物理接続を信頼し、認証・暗号は実装しない。ただし入力長、型、範囲、状態の検証を省かない。USB VID/PIDは試作設定と製品用の正式値を分け、使用する具体値・文字列はO-15で決める。

書込みはWCH-Linkまたは内蔵USB ISP。独自DFU/UF2/IAPは今回対象外。`generic_isp`/`evt_isp`は既存のアップロード設定であり、現時点で実機書込み成功を保証したものではない。
