# ファームウェア要求仕様

記録日: 2026-09-17。状態: 仕様策定中／実装未着手。

本書はこれまでの合意を保存する仕様スナップショットであり、実装開始の承認を意味しない。「確定」は会話で合意済み、「暫定」は提案・検証待ち、「未決」は追加判断が必要な事項を表す。実測済みという意味ではない。未決事項には [decisions.md](decisions.md#未決事項台帳) の `O-xx` を付す。実装者が推測で埋めてはならない。

## 目的と利用者

BVE系鉄道シミュレータ用のI/Oコントローラ兼通信ゲートウェイを構築する。PCのBIDS通信または別MCUのCANopenマスターから受けた情報で表示・出力を制御し、スイッチやアナログ操作器の入力を選択した経路へ送る。利用者は試作機の開発者・調整担当者・運用者とする。

まずCH32V203 EVTで機能を検証し、ボード固有部分を差し替えてカスタム基板へ移植できる構成にする。製品化に向けた保守性は確保するが、機能安全認証や実機アクチュエータの安全制御は今回の対象外とする。

## 現状と対象範囲

現在のリポジトリはPlatformIO `noneos-sdk`プロジェクトであり、`src/main.c`がPC1を1秒ごとに反転する。USB/BIDS、CANopen、下記I/O機能はまだ実装されていない。既存環境は`generic`、`evt`、`generic_isp`、`evt_isp`である。

今回の対象はファームウェア、ボードプロファイル、ホスト単体試験、実機試験手順、仕様・設計文書である。負荷駆動回路、ESP32マスターのソフトウェア、独自更新ブートローダ、設定の永続保存、CAN FDは対象外とする。

## ユースケース

| ID | 操作・状況 | 期待する結果 |
|---|---|---|
| UC-01 | PCからBIDSの速度とドア状態を受ける | 速度をPWMへ、ドア閉状態をDOへ変換する |
| UC-02 | DIを操作し、ADCブレーキ操作器を動かす | 選択経路にキー押下・解放、ブレーキ段またはI/O値を通知する |
| UC-03 | CANopenマスターがノードを起動・設定する | LSSでIDを割り当て、設定後にPDOでI/Oを扱える |
| UC-04 | USB/CANの操作経路を切り替える | 一定の猶予内に新経路へ引き継ぎ、失敗時は安全値へ移行する |
| UC-05 | 通信断、入力異常、bus-offが発生する | 出力を規定状態にし、診断を通知・表示する |
| UC-06 | 計器やボードを交換する | プロファイル、変換設定、出力上限で対応できる |

## 機能要求（What / Why）

具体的なピン、データ型、時刻の定義は [interface-spec.md](interface-spec.md) を正とする。

| ID | 要求 | 目的・理由 |
|---|---|---|
| R-01 | DI、DO、PWM、ADCを各1ch、モード入力、RUN/ERROR LEDを提供する | 最小構成で一連の入出力を検証する |
| R-02 | ボード別ピン・周辺機能をビルド時に指定する | EVTとカスタム基板を同じアプリケーションで扱う |
| R-03 | 操作経路の3方針をビルド時選択でき、既定をGPIO厳密選択にする | 配線選択とUSB優先運用の両方に対応する |
| R-04 | 出力指令と入力由来の操作は選択経路に限定し、状態・診断は両経路で参照可能にする。CANopen公開は使用値と状態/診断に限定し、未使用BIDS値を網羅公開しない | 操作権の競合と不要な公開・容量増を避ける |
| R-05 | USB CDCでBIDSクライアントとしてテキストとB64Eを扱う | 現行BIDS_Serverと旧版の互換性を確保する |
| R-06 | 自動送信を優先し、代替取得は必要な各データ20 Hzを目標とする。生存確認が正常なら最終値を保持し、確認用の周期再取得は追加しない | 不変値を断線と誤認しない。通知だけが停止する故障の検出限界を受容する |
| R-07 | BIDSのSpec/State/Handle/Panel/Soundと上限付き可変構造を扱う | 固定メモリで必要な情報を受信する |
| R-08 | CANopen slaveとしてLSS、NMT、Heartbeat、SDO、PDO、EMCYを提供し、マスターHeartbeat監視は既定有効とする | 別MCUマスターから設定・制御し停止を監視する |
| R-09 | 毎起動LSSで揮発Node-IDを割り当て、遅れて起動するノードにも対応する | 固定IDの書込み作業を不要にする |
| R-10 | CiA 401を基本にI/Oを公開し、PDOの初期割当てとPre-operational時の再マッピングを提供する | 起動容易性と構成変更を両立する |
| R-11 | 論理マッピング・変換・極性・安全値を設定可能にし、再起動でビルド既定値へ戻す | ハード配線を変えずに用途を調整する |
| R-12 | 既定はPre-operational中の明示applyで設定を検証・一括反映し、ビルド設定による独立項目の即時反映にも対応する。Operational遷移だけでは未反映設定を採用しない | 不整合な部分設定の公開を防ぐ |
| R-13 | 線形変換、オフセット、反転、上下限、閾値、ヒステリシスを提供する | 計器・操作器の差を吸収する |
| R-14 | PWMを16 bit論理値とし、速度上限と独立調整用Pmaxを分離する。選択経路から動作中にPmaxを変更し、有効入力で次回出力更新時に再計算する。USBは速度絶対値、CANは指令をPmaxへ比例換算する | 計器の感度を両経路で調整し、安全状態は維持する |
| R-15 | DIデバウンスとADC平滑化・変化通知を提供し、ADC通知の変化量/最大間隔をSDOで揮発変更可能にする | チャタリング・ノイズと通信量を調整する |
| R-16 | 可変抵抗ADCの校正と診断を分離し、8標本平均が範囲外100 msで非常ブレーキ、正常100 msで自動復帰する。BIDS段数未取得時は指令を送らない | 端点操作と故障を区別し、不明な段数を推測しない |
| R-17 | 起動・通信断・NMT離脱の安全状態を定義する。モード入力は20 ms安定、DO/PWMは新経路の両指令で一括引継ぎし、最大3秒で揃わなければ両方安全値。Hornは解放・再押下まで引き継がない | 意図しない出力保持・部分切替・操作を防ぐ |
| R-18 | 選択CANのbus-offは安全出力後に自動復旧する。通信復旧は運転条件と新しい有効指令で自動再開し、DO/PWMとも通信断前の指令を再利用しない。正常USB操作は非選択CAN停止/異常で止めない。致命異常は安全出力とコード表示で停止する | 回復可能性と故障範囲を区別する |
| R-19 | RUN/ERROR LED、診断OD/EMCY、専用ログで観測可能にする。非選択CANの実通信故障もERROR表示する。Releaseは起動/状態/異常、詳細追跡はDebug | 出力停止の条件と故障の観測を分離する |
| R-20 | Releaseでウォッチドッグを有効にし、Debugのみ無効化を許す | ハング検出とデバッグ操作を両立する |

R-03/04/06/12/14/16/17/18/19は方向性が確定しているが、境界条件・通信形式等に未決事項を含む。要求の存在と実装詳細の確定を混同しない。

## 非機能要求と制約

| ID | 要求・目標 | 背景・確認事項 |
|---|---|---|
| R-21 | 1 ms tick、完全な有効フレーム受信から出力レジスタ更新まで最悪5 ms以内 | PC生成時間、伝送時間、入力フィルタ時間は含めない。負荷条件はO-13 |
| R-22 | 自作部C++20、例外/RTTI/動的確保なし、短いISRと非ブロッキング処理。混雑時は連続値の最新化と押下/解放の順序保持を優先し、保持不能は明示異常。ツールチェーン適合は実装工程で検証 | 言語方針と組み込み時間・容量制約を両立する |
| R-23 | Flash目標56 KB以下、静的RAM目標14 KB以下。64 KB Flash/20 KB RAMの実容量内でスタック余裕を確保する | 閾値は目標と物理限界を区別する。詳細予算はO-12 |
| R-24 | 屋内0～40℃、結露なし、連続運転、USB給電を前提とする。低消費電力動作・電源種別の自動判別は対象外 | 試作の運用条件を固定する |
| R-25 | 物理接続を信頼し、認証・暗号化を実装しない。負荷駆動保証はMCU論理信号まで | 信頼境界と電気的責務を限定する |
| R-26 | WCH-Linkと内蔵USB ISPによる書込みを使用する | 独自DFU/IAPによるFlash消費を避ける |
| R-27 | Unity単体試験、全ターゲットビルド、HILで検証する。重要ロジックの分岐カバレッジ90%以上を目標とする | 要求と試験を追跡可能にする |
| R-28 | 自作コードはGoogle基準に4スペース・.cpp/.hpp・関数/クラス/構造体宣言へのDoxygen必須を上書きする。日本語文書を随時更新・再読し、プロンプト境界にかかわらず意味ある作業の最小単位でこまめにコミットする | 一貫したコードと宣言側の契約から設計・検証結果を引き継ぎ、変更の影響範囲を小さくする |
| R-29 | 許可されたgoalと測定可能な完了条件に向け、計画・実装・ビルド・原因解析・修正・再ビルド・書込み・ログ取得/解析を自律反復する | 手順ごとの再指示を待たず、検証済みの成果へ到達する |

| R-31 | read-only調査・解析・レビューを適宜委譲し、実装・試験・文書も所有範囲を分けて積極的に並列化する | 独立した仕事を同時に進め、共有ファイル・ビルド・実機の競合を防ぐ |

コード規約の正本は [coding-style.md](coding-style.md)。Google基準への組み込み例外、上流ライブラリへの適用除外、既存コードの適合化を後日に行う移行方針を定める。

## 未決・対象外

実装前に優先して解決する残件は、PWM上限のUSB変更手段・設定API（O-04）、BIDS取得方式切替（O-05）、経路切替と複合故障の優先順位（O-06）、ODとワイヤ形式（O-07/08）、ADC診断の詳細（O-09）、タイミング測定条件（O-13）である。部分確定したO-IDも残件が解消するまで維持する。

実機ピン・クロック確認（O-01/02）、カスタム基板（O-03）、USB識別子（O-15）、CANマスター（O-16）も別途必要とする。今回未採用の永続保存、CAN FD、独自更新、BIDSサーバ役等は [decisions.md](decisions.md) に理由と将来課題を残す。具体的な検証対応表は [test-plan.md](test-plan.md) を参照する。
